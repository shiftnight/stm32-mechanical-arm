# STM32 机械臂项目：从整体到关键代码

这份讲解按“先看系统，再看数据如何流动，最后看算法和硬件细节”的顺序组织。源码目录在 `机械臂/机械臂/`。重点学习自写的 `User/`、`Application/`、`Hardware/`；`Library/` 和 `Start/` 主要是芯片厂商/内核支撑代码。

## 1. 先给项目定性

这是一个运行在 **STM32F103C8、Cortex-M3** 上的裸机固件。它没有操作系统，主程序以 `while(1)` 轮询任务；串口接收、系统滴答、舵机脉冲则由中断异步完成。项目围绕六路实体舵机，提供串口控制、PS2 手柄输入、动作组保存/回放、外部 Flash 参数保存，以及一个平面连杆逆运动学尝试。

可以把整套系统看成：

```text
输入：串口命令 / PS2 手柄 / 按键
                 │
                 ▼
应用逻辑：命令解析、动作组、按键映射、逆运动学
                 │
                 ▼
硬件驱动：GPIO、USART、SPI Flash、定时器、舵机脉冲
                 │
                 ▼
输出：舵机信号 / 串口回复 / 蜂鸣器 / LED
```

**最关键的一条控制链**是：

```text
串口收到完整命令
 → USART 接收中断把字节放进缓冲区
 → 主循环 app_usart_run() 选择命令处理器
 → parse_action() 得到舵机编号、目标脉宽、运动时间
 → duoji_doing_set() 写入 aim/inc
 → TIM2 中断周期性输出舵机脉冲并更新 cur
 → 舵机根据脉宽转动
```

理解这条链，就抓住了项目的主干。

## 2. 工程分层：每一层回答不同问题

| 目录 | 你应该问的问题 | 本项目中的例子 |
|---|---|---|
| `Start/` | 芯片复位后如何进入 C 程序？内核和寄存器如何描述？ | 启动汇编、中断向量表、Cortex-M3 头文件、系统时钟变量 |
| `Library/` | 如何用厂商提供的接口配置外设？ | `GPIO_Init()`、`USART_Init()`、`TIM_TimeBaseInit()` |
| `Hardware/` | 如何把某种外设操作封装成可复用驱动？ | `h_servo.c`、`h_usart.c`、`h_flash.c`、`h_timer.c` |
| `Application/` | 收到输入以后要执行什么产品逻辑？ | 解析命令、PS2 按键映射、动作组管理、逆运动学 |
| `User/` | 整个程序从哪里启动，初始化顺序是什么？ | `main.c` 和中断服务函数文件 |
| `MDK-ARM/` | 哪个芯片、哪些源文件、哪些编译选项组成工程？ | `project01.uvprojx` |

分层的好处是：应用层不必自己写 GPIO 寄存器；驱动层也不需要知道“这个串口命令代表夹爪张开”。上层表达意图，下层落实动作。

## 3. 从复位到主循环：`main()` 在做什么

`User/main.c` 是阅读起点。启动汇编先设置栈和中断向量，随后进入 `main()`。初始化大体分成几段：

1. `rcc_init()`：从外部 8 MHz 晶振经 PLL 配置系统时钟；代码目标是 72 MHz。
2. `SWJ_gpio_init()`：重映射调试引脚，为 PB3/PB4 等复用引脚腾位置。
3. `SysTick_Init()`：启用每 1 ms 一次的系统滴答。
4. 给 8 个舵机状态槽设置初始值。
5. 初始化 LED、蜂鸣器、按键；发出启动提示。
6. 初始化 USART1/USART3、SPI2 外部 Flash，读取保存参数和舵机上次位置。
7. 初始化舵机 GPIO，启动 TIM2 脉冲调度。
8. 初始化 PS2 手柄，设置连杆长度。
9. 进入 `while(1)`，反复调用 LED、按键、串口、动作组、PS2 和位置保存任务。

舵机初始化顺序值得理解：先为状态数组赋初值，再从 Flash 恢复上次位置，再把 GPIO 配成输出，最后启动定时器。这样能减少“上电时先输出错误脉宽、舵机突然冲向一端”的机会。这个保护不能替代机械限位和电源设计，但它体现了**初始化顺序会影响物理设备行为**。

主循环里的 `app_*_run()` 通常是短任务：检查时间或标志，没到执行时机就立即返回。真正的时基来自 SysTick。例子：LED 约每 1000 ms 翻转；PS2 每 50 ms 读取；按键由 SysTick 每 10 ms 扫描；静止后最多每 30 秒尝试保存位置。

## 4. 裸机程序里的两种“同时做事”

### 主循环（前台）

`while(1)` 按顺序轮询。每个任务应尽可能快地返回，避免一个长任务拖住其他任务。这个项目用 `millis()` 判断是否到时，LED/PS2 等大多不需要每轮都做实际工作。

### 中断（后台响应）

- **SysTick**：每 1 ms 增加毫秒计数，并每 10 ms 扫描按键。
- **TIM2**：按设定的时间间隔切换舵机 GPIO 高/低电平，形成脉冲。
- **USART1/USART3**：每收到一个字节就进入接收中断，累积成一条命令。

中断服务函数应短小。串口中断这里只收字节和判断结束符；命令解析放到主循环，这样不让复杂字符串处理长期占用中断上下文。

## 5. 舵机是怎样被控制的

### 脉宽代表位置

普通位置舵机通常看周期约 20 ms 的脉冲。项目用脉冲高电平宽度表达目标位置：中间值约 1500 μs，常用命令范围 510–2490 μs。具体角度和脉宽对应关系取决于舵机型号、安装方向和机械结构；不能把 1500 μs 当成经过标定的绝对“90 度”。

### 软件如何产生多路脉冲

`TIM2_Init(2000, 72 - 1)` 把定时器计数频率设为约 1 MHz，因此一个计数约为 1 μs。TIM2 更新中断里，`flag` 在高电平阶段和低电平阶段之间切换：

- 高电平阶段：`ARR = cur_pwm`，对应脉冲高电平时长。
- 低电平阶段：`ARR = 2500 - cur_pwm`，补足约 2.5 ms 的单路时隙。
- 每完成一路的高低电平，就切换下一个逻辑舵机编号。

8 个逻辑时隙 × 约 2.5 ms ≈ 20 ms，所以每一路大约每 20 ms 得到一次新脉冲。这里是用**定时器中断 + 普通 GPIO**拼出多路脉冲，不是直接把 TIM2 的硬件 PWM 通道接到舵机。

### 平滑运动的插值

每个舵机的状态结构体有 `cur`（当前脉宽）、`aim`（目标脉宽）、`time`（运动时间）、`inc`（每帧变化量）。设置目标时大致计算：

```text
每帧增量 inc = (目标脉宽 aim - 当前脉宽 cur) / (运动时间 / 20ms)
```

例如当前 1500 μs，目标 2000 μs，时间 1000 ms：预计有 50 帧，每帧约增加 10 μs。TIM2 每次轮到该舵机时更新 `cur += inc`，看起来就从当前位置平滑移向目标。`duoji_doing_set()` 同时把目标裁剪到限位范围；时间少于 20 ms 时直接设置到目标。

### 6 路实体输出与 8 个逻辑槽

代码里 `DJ_NUM` 是 8，但 `h_servo.c` 的引脚输出只实现了编号 0–5：

| 编号 | 引脚 | 注释中的用途 |
|---:|---|---|
| 0 | PB3 | 底座 |
| 1 | PB8 | 肩关节 |
| 2 | PB9 | 肘关节 |
| 3 | PB6 | 腕关节 |
| 4 | PB7 | 腕部角度 |
| 5 | PB4 | 夹爪 |
| 6、7 | 无 GPIO 输出 | 保留的空槽 |

所以串口编号是**从 0 开始的数组下标**。`#001...` 操作的是下标 1，也就是第二路实体输出，不是自然语言里的“第 1 路”。代码注释偶尔把索引当编号说，阅读时以 `servo_pin_set()` 的 `switch` 为准。

## 6. 串口协议与一次命令的完整拆解

USART1 和 USART3 都配置为 115200、8N1（8 个数据位、无校验、1 个停止位）。每个接收中断拿到一个字节；接收起始符决定模式，收到终止符后补 `\0` 并置完成标志。主循环看到标志后分发处理。

| 起始符 | 终止符 | 处理入口 | 用途 |
|---|---|---|---|
| `$` | `!` | `parse_cmd()` | 系统命令、复位、动作组、逆运动学等 |
| `#` | `!` | `parse_action()` | 舵机动作 |
| `{` | `!` | `parse_action()` | 一条消息里放多条舵机动作 |
| `<` | `>` | `save_action()` | 保存预命令或动作组 |

命令 `#001P2000T1000!` 可逐字符读成：

- `#`：舵机动作消息开始。
- `001`：逻辑舵机索引 1。
- `P`：后面是绝对目标脉宽 Position。
- `2000`：目标脉宽 2000 μs。
- `T`：后面是时间 Time。
- `1000`：1000 ms 完成。
- `!`：消息结束。

对应调用最终是 `duoji_doing_set(1, 2000, 1000)`。多个动作可以连在花括号里，例如 `{#000P1500T1000!#001P2000T1000!}`；解析器在字符串中寻找多个 `#...P...T...!` 片段。

另外两种舵机命令：

- 相对移动：`#001PR+0500T1000!`，从当前脉宽增加 500 μs，约 1 秒完成。
- 停止：`#001PDST!`；`$DST!` 则停止全部逻辑槽。
- 校准偏差：`#001PSCK+050!`，修改对应通道的 PWM 偏差并写入外部 Flash。

系统命令在 `parse_cmd()`：`$DJR!` 回中，`$RST!` 软件复位，`$DGS:n!` 回放一组，`$PTG:x-y!` 读出组内容，`$DGT:x-y,count!` 顺序执行一段组。当前实现中 `count=0` 表示不按有限次数结束，通常会循环执行。

## 7. 动作组与外部 Flash

板上 W25Q64 是 **8 MiB 外部 SPI Flash**。变量名 `eeprom_info` 是项目沿用的名字；它不是 STM32 内置 EEPROM。

- 每个动作组占 `ACTION_SIZE = 256` 字节，组号 `n` 的起始地址是 `n × 256`。
- 配置结构体保存版本标记、舵机偏差、开机预命令和上次舵机位置。
- 配置区域放在最后一个 4 KiB 扇区，地址由 `W25Q64_INFO_ADDR_SAVE_STR` 计算得到（0x7FF000）。
- Flash 擦除以 4 KiB 扇区为单位，编程以 256 字节页为单位；写入前通常要检查是否需要擦除。

这带来一个重要设计概念：**存储布局是固件协议的一部分**。组大小、组号到地址的换算、参数区位置必须协调，不能随意改一个宏就认为迁移完成。

## 8. PS2 手柄输入

`h_ps2.c` 用 GPIO 模拟类似 SPI 的时序读取手柄。应用层 `app_ps2_run()` 每 50 ms 轮询一次，检查连接模式和 16 位按键状态。PS2 协议是低电平表示按下，因此代码通过 XOR 找出发生变化的位：

- 位从 1 变 0：提取预设字符串中 `^` 前的“按下命令”。
- 位从 0 变 1：提取 `^` 后的“松开命令”，通常是停止舵机。

红灯模式映射为机械臂关节动作；绿灯模式表里是四轮底盘的 `$DCR` 命令，但当前 `parse_cmd()` 没有 `$DCR` 的处理分支，因此不能仅凭这张映射表就认为本固件完整实现了底盘控制。

## 9. 逆运动学：从末端坐标反求关节

`Hardware/kinematics/h_kinematics.c` 假定机械臂由底座旋转、肩/肘平面连杆和末端夹爪构成。`main()` 设置的长度为 100、105、88、155 mm（底座高度、大臂、小臂、末端长度）。

主要思路：

1. 输入末端 `(x,y,z)` 和末端角 `Alpha`。
2. 用 `atan2(y,x)` 求底座角，把三维位置投影成平面径向距离。
3. 减去末端长度在水平/垂直方向上的投影，得到腕部目标点。
4. 用两连杆几何关系和余弦定理求肩、肘角。`acos()` 的输入必须落在 [-1,1]，超出通常表示目标不可达或数值异常。
5. 用关节角范围做可达性过滤，再把角度映射到 PWM。源码采用 `PWM = 1500 - 2000 × angle / 270`，因此还要结合各舵机的安装方向理解正负号；生成最终命令前，代码又对 3 号关节做了一次 `3000 - PWM` 反向处理。
6. `kinematics_move()` 扫描多个 `Alpha` 候选，选出一个可行姿态，拼成 0–3 号舵机命令。

这是解析几何的逆运动学，不是通用机械臂求解器：坐标系方向、连杆尺寸、舵机零位和机械安装偏角都必须与实际机构一致。当前输出只控制 0–3 号舵机，没有计算夹爪 5 号的开合。

## 10. 读这个项目时顺手夯实的 C / MCU 基础

### `.h` 和 `.c`

头文件通常放类型、宏、函数声明和 `extern`；源文件放函数实现和全局变量的实际定义。`extern` 的意思是“变量在别的 `.c` 文件里定义”。一个全局变量只能有一处实体定义，否则会重复定义。

### 指针和缓冲区

`u8 *buf` 是指向字节的地址。串口中断把字节写到 `uart_receive_buf[index]`，字符串函数把同一片内存视为以 `\0` 结尾的字符串。写入时必须同时保证容量足够、存在结束符、解析出的数组下标合法。

### 宏与数组索引

`DJ_NUM` 影响数组长度和循环边界；`servo_pwm_min[index]` 是按舵机编号取限位。宏替换发生在编译前，数组越界则是运行期问题，编译器未必能替你挡住。

### 时钟、总线与外设时钟

RCC 不只是“设置 CPU 速度”，还负责给 GPIO、USART、SPI、TIM 等外设开时钟。代码先开对应 RCC 时钟，再配置外设寄存器，这是 STM32 初始化的常见顺序。

### 中断共享变量

主循环和中断共同读写的标志、计数器、缓冲区应仔细考虑 `volatile`、原子性和缓冲区所有权。本项目有若干共享变量未声明为 `volatile`；在优化等级变化或高频并发接收时，可能出现主循环读到旧值或数据覆盖的问题。

## 11. 源码中需要特别留心的边界和不一致

这些点适合作为学习时的“工程审查练习”，不代表你基础差：

1. **逆运动学串口格式不匹配。** 文档式用法会是 `$KMS:x,y,z,time!`，但 `parse_cmd()` 的 `sscanf` 格式字符串以 `KMS:` 开头，没有跳过最前面的 `$`，所以按 UART 模式接收时很可能解析失败。修复时应统一协议格式，并检查 `sscanf` 是否成功读到全部字段。
2. **绝对动作解析缺少舵机下标前置校验。** `parse_action()` 在给 `duoji_doing_set()` 之前就用 `index` 访问 `eeprom_info.dj_bias_pwm[index]`。坏包或超范围编号可能越界。网络/串口输入都要先验证格式、数字和范围。
3. **动作组读写缺少完整地址边界检查。** 组号映射到 `group_num * 256`，应保证它不会撞上最后的配置扇区，也要限制读取/执行的组号范围。
4. **两个串口共用一套接收状态。** USART1 和 USART3 共用 `uart_receive_buf`、模式和完成标志，不能可靠地同时接收两条命令。
5. **按键 1 是 Flash 测试动作。** `app_key_run()` 会擦除外部 Flash 的第 0 扇区并写测试字节；第 0 组动作若保存在该扇区，会被覆盖。理解代码时把它当调试功能，不要把它误认为普通的安全按键功能。
6. **`GPIO_Remap_SWJ_Disable` 影响调试。** 这不只是释放 JTAG，也会关闭 SWD 调试接口；若调试器突然连不上，要检查这段引脚重映射。
7. **注释、IDE 配置和运行时配置可能不完全一致。** `rcc_init()` 明确配置 HSE × 9 为 72 MHz；Keil 工程文件中的 `CLOCK(12000000)` 是另一个配置字段。最终频率要以实际晶振和运行配置共同核实，不能只看注释。
8. **限位是脉宽软件限位，不是机械碰撞检测。** 还需要实物校准舵机方向、端点、关节干涉和电源能力。

## 12. 建议的源码阅读顺序与练习

按这个顺序读，能逐步建立架构感：

1. `MDK-ARM/project01.uvprojx`：确认芯片、启动文件、工程源文件。
2. `User/main.c`：画初始化顺序和主循环清单。
3. `Hardware/timer/h_timer.c`：分别追 `SysTick_Handler()` 和 `TIM2_IRQHandler()`。
4. `Hardware/servo/h_servo.c`：弄清状态结构体、脉宽限位、插值公式。
5. `Hardware/usart/h_usart.c`：追接收中断如何决定模式和结束一条命令。
6. `Application/app_usart/app_usart.c` → `Application/app_servo/app_servo.c`：追一条命令到目标位置。
7. `Hardware/flash/h_flash.c` 和 `Application/app_servo/app_servo.c`：画出 Flash 地址布局及读写过程。
8. `Application/app_ps2/app_ps2.c`：从按键位变化追到命令字符串。
9. `Hardware/kinematics/h_kinematics.c`：最后再学几何模型和可达性判断。

建议先做三道纸上练习：

- 若当前 1400 μs，目标 1800 μs，运动时间 800 ms，每 20 ms 大约改变多少？（400 ÷ 40 = 10 μs。）
- `#004P1200T0500!` 最终会影响哪个 GPIO？（下标 4，对应 PB7。）
- PS2 按下后为什么要有松开命令？（按下命令启动相对运动，松开命令让舵机停止，形成“按住持续动”的手柄体验。）

如果这三题能从代码链路解释清楚，再尝试改一个简单功能：新增一个只读串口状态命令，先做输入校验，再输出当前 `cur/aim`，不要一上来改定时器或逆运动学。
